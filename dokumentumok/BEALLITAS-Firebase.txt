MI EZ AZ APP?
  A Rendli egy vállalkozáskezelő (megrendelések, projektek, ügyfelek,
  számlák, bevétel/kiadás). A tulaj bejelentkezik, és a saját üzleti
  adatait kezeli a felhőben (Firestore: vaults/{uid}).
  PLUSZ: generál egy BEÁGYAZHATÓ megrendelő-űrlapot, amit idegen
  weboldalba is beteszel. Az ott leadott rendelés a Firestore-ba kerül,
  és ÉLŐBEN megjelenik a Rendli-fiókodban.

  Két Firebase-szolgáltatás kell:
    - Authentication → a tulaj bejelentkezése (e-mail/jelszó).
    - Firestore     → a tulaj adata + a beérkező rendelések + a form-konfig.

  A Rendli weboldalt (és a beágyazható megrendelő-űrlapot) NEM a Firebase
  Hosting szolgálja ki, hanem GitHub (GitHub Pages). A Firebase itt csak
  adattárolás (Auth + Firestore).

5) FIRESTORE SZABÁLYOK — MAGYARÁZAT (firestore.rules)
----------------------------------------------------------------------
Három rész:

  a) A tulaj privát adata:
       match /vaults/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     → csak a bejelentkezett tulaj éri el a SAJÁT adatát.

  b) Nyilvános form-konfiguráció (a widget ebből tölti a szolgáltatásokat/
     mezőket — nem érzékeny adat):
       match /form_configs/{uid} {
         allow read: if true;                          // bárki OLVASHATJA
         allow write: if request.auth != null && request.auth.uid == uid;  // csak a tulaj írja
       }

  c) Beérkező rendelések inboxa (a nyilvános űrlap ide ír):
       match /inbox/{uid}/items/{docId} {
         allow create: if request.resource.data.size() < 40;  // bárki LÉTREHOZHAT (méretkorlát)
         allow read, delete: if request.auth != null && request.auth.uid == uid;  // csak a tulaj olvassa/törli
       }

  d) Aláírandó szerződések (a megrendelő az e-mail linkjéből nyitja/írja alá):
       match /contracts/{uid}/docs/{docId} {
         allow read: if true;   // bárki OLVASHATJA a véletlen tokennel
         allow create, update, delete: if request.auth != null && request.auth.uid == uid;
       }
     → a szerződés szövegét bárki elolvashatja, akinek megvan a kitalálhatatlan
       link; írni/aláírt példányt visszaírni csak a tulaj tud. Az aláírás maga a
       fenti inboxon át érkezik vissza.

Így a beágyazott űrlap (bejelentkezés nélkül) LÉTRE tud hozni egy
rendelést, de olvasni/törölni csak a tulaj tud. A "firebase deploy
--only firestore:rules" a szabályt automatikusan felteszi.

FIGYELEM: a "contracts" gyűjtemény ÚJ — a szerződés-aláírás csak azután
működik, hogy a frissített szabályt felteszed:
    cd firebase && firebase deploy --only firestore:rules

9) (AJÁNLOTT) APP CHECK — bot-védelem a nyilvános íráshoz
----------------------------------------------------------------------
Mivel a megrendelő-űrlap NYILVÁNOSAN ír, botok spammelhetik a beérkező
listát. Ez ellen az App Check (reCAPTCHA v3) véd.
FIGYELEM: a reCAPTCHA domain-hez kötött — a beágyazott widgetet csak
azokon a domaineken engedi, amiket a reCAPTCHA-hoz felveszel. Ha "bárhová"
ágyazod, ez korlátozó. Amíg kevés, ismert oldalra teszed, praktikus.
  Console → Build → App Check → a Web app → Register → reCAPTCHA v3
  → a site key a kódba, a secret a Firebase-be. Először "Unenforced"!
